# 接入 GitHub MCP

> 本节介绍如何通过 MCP 将 Agent 与 GitHub 工作流连接起来，并从只读能力开始逐步验证。

- 难度：🟡 进阶
- 建议学习时间：20～35 分钟
- 状态：具体 MCP Server、客户端配置格式和授权流程待实测

## 学习目标

- 理解 GitHub MCP 在 Agent 工作流中的位置。
- 知道 MCP Server、Client 与 GitHub API 的关系。
- 安全配置 GitHub 身份验证。
- 先验证只读操作，再考虑写入操作。

## 1. 工作关系

```text
用户
 │
 ▼
Agent / Harness
 │
 ▼
MCP Client
 │
 ▼
GitHub MCP Server
 │
 ▼
GitHub API
 │
 ▼
仓库、Issue、Pull Request 等资源
```

MCP 负责约定客户端与服务端之间的交互方式；GitHub MCP Server 则将部分 GitHub 能力以 MCP 方式提供给客户端。实际可用工具取决于所选 Server 的实现和授权范围。

## 2. 配置前准备

- GitHub 账号。
- 需要访问的目标仓库。
- 支持 MCP 的客户端或 Harness。
- 选定并核实可信的 GitHub MCP Server。
- 阅读 Server 的官方配置说明和权限要求。

## 3. 权限原则

建议按以下顺序进行：

1. 先使用只读能力。
2. 仅授权完成任务所需的仓库范围。
3. 确认 Agent 能正确读取仓库、Issue 或 PR 信息。
4. 如确实需要写入，再单独评估写入权限。
5. 创建 Issue、提交评论、修改文件、合并 PR 等操作应设置明确确认机制。

不要为了演示方便直接授予所有仓库的全部权限。

## 4. 配置步骤

> 以下为通用步骤。实际 Server 名称、安装方式、配置字段、认证机制和工具名称必须以选定实现的官方文档为准。

1. 选择可信的 GitHub MCP Server。
2. 阅读其安装和安全说明。
3. 根据客户端要求配置 Server 启动方式。
4. 使用官方推荐方式完成 GitHub 身份验证。
5. 在客户端中启用 MCP Server。
6. 检查连接状态和已暴露工具列表。
7. 先执行只读测试，例如查看指定仓库的基本信息。
8. 确认结果正确后，再测试其他只读能力。

## 5. 建议的测试任务

- 查询指定仓库的基本信息。
- 列出最近的 Issue。
- 查看某个 Pull Request 的状态。
- 读取指定文件内容。
- 汇总仓库近期变更。

测试时记录调用的工具名称、输入参数、返回结果和所需权限。不要在公开教程中展示 Token。

## 6. 写入操作的确认边界

下列操作属于写入或高影响操作，教学演示应明确说明并要求用户确认：

- 创建或关闭 Issue。
- 发布评论。
- 创建分支或提交修改。
- 创建 Pull Request。
- 合并 Pull Request。
- 删除仓库内容或修改仓库设置。

Agent 能调用工具，不代表它应该自动获得执行所有操作的授权。

## 7. 常见问题

| 问题 | 检查方向 |
|---|---|
| MCP Server 无法启动 | 运行时、依赖、启动命令和日志 |
| 客户端无法连接 | 配置格式、传输方式和进程状态 |
| GitHub 认证失败 | Token 状态、认证方式和权限 |
| 看不到目标仓库 | 仓库授权范围和账号访问权限 |
| 工具列表为空 | Server 是否正确注册和暴露工具 |
| 写入操作失败 | 仓库权限、分支保护和操作确认 |

## 本节小结

GitHub MCP 能把仓库协作能力接入 Agent 工作流，但安全配置比“成功连上”更重要。先只读、后写入，先最小权限、后按需扩展。
