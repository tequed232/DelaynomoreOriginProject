# 从 Claude 提示词制作 Skills

> 本节介绍如何把一套已经验证有效的提示词和工作方法，整理成可复用、可维护的 Skill。

- 难度：🟡 进阶
- 建议学习时间：20～40 分钟
- 状态：Skill 目标运行环境及其文件规范待按实际采用的规范核实

## 学习目标

- 区分普通提示词与 Skill。
- 学会从提示词中提取任务目标、步骤、约束和验收标准。
- 将用户已有的 Claude 提示词整理为结构化 Skill。
- 验证 Skill 是否稳定、可复用。

## 1. 提示词和 Skill 有什么区别？

提示词（Prompt）通常是一次交互中给模型的指令。

Skill 更强调可复用的任务能力：它不仅可以包含指令，还可以包含任务流程、输入要求、参考资料、脚本或其他资源。不同 Agent 平台对 Skill 的文件结构和加载方式可能不同。

因此，不能假设一份 Skill 文件可以不经修改就在所有平台通用。

## 2. 从一份提示词开始

本教程使用维护者已有的 Claude 提示词作为素材。

正式编写时，应由维护者提供允许公开的提示词版本。涉及私有项目、密钥、个人信息或第三方保密内容的部分必须先移除。

## 3. 提取提示词中的结构

把原始提示词拆成以下部分：

| 部分 | 需要提取的问题 |
|---|---|
| 任务目标 | 这个提示词要完成什么工作？ |
| 触发条件 | 在什么情况下应该使用？ |
| 输入 | 用户需要提供哪些信息？ |
| 工作步骤 | 应该按什么顺序完成？ |
| 输出格式 | 最终结果应该长什么样？ |
| 约束 | 哪些事情不能做？ |
| 验收标准 | 如何判断结果合格？ |
| 异常处理 | 信息缺失或任务失败时怎么办？ |

## 4. Skill 草案模板

以下仅是概念模板，正式文件格式必须以目标 Agent 平台的 Skill 规范为准。

```markdown
# Skill 名称

## 用途
说明该 Skill 解决的问题。

## 适用场景
列出触发条件和不适用场景。

## 输入要求
列出必须信息、可选信息和缺失信息的处理方式。

## 执行流程
1. 理解目标。
2. 检查输入。
3. 制定执行计划。
4. 执行任务。
5. 验证结果。

## 输出要求
说明输出结构、语言和格式。

## 安全约束
说明权限、隐私和高影响操作的确认要求。

## 验收标准
列出可检查的完成条件。
```

## 5. 如何验证 Skill？

至少设计三类测试：

1. **正常输入**：信息完整，检查能否按预期完成任务。
2. **信息缺失**：缺少关键条件，检查是否会先询问，而不是擅自编造。
3. **边界场景**：出现冲突要求、无权限操作或危险操作，检查是否遵守限制。

对比原始提示词和 Skill 的表现，确认结构化后是否提升了稳定性和可复用性。

## 6. 重要原则

- 不要把提示词中的每一句话机械地搬进 Skill。
- 去除只对某一次任务有效的临时信息。
- 保留真正影响质量的约束和验收标准。
- 将频繁变化的信息放在可维护的配置或资源文件中。
- 不要承诺 Skill 能突破模型、平台或权限系统的限制。
- 记录 Skill 的适用平台和版本。

## 本节小结

Skill 的重点不是“把提示词变长”，而是把一套有效的任务方法整理成可复用、可测试、可维护的能力单元。
