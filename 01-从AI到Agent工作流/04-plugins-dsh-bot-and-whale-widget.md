# Plugins：以 dsh-bot 和 dsh-whale-widget 为例

> 本节以 `dsh-bot` 和 `dsh-whale-widget` 为例，介绍如何理解、安装、配置和验证 Harness 插件。

- 难度：🟡 进阶
- 建议学习时间：20～30 分钟
- 状态：插件来源、版本、安装命令和能力范围待按实际仓库核对

## 学习目标

- 理解 Plugin 与模型、Skill、MCP 的区别。
- 能够查找插件的来源和依赖。
- 学会按文档安装、配置和测试插件。
- 知道插件可能获得哪些权限。

## 1. Plugin 是什么？

Plugin（插件）是为宿主程序扩展能力的组件。它通常依赖宿主提供的扩展接口，并可能访问文件、网络、消息平台或其他服务。

插件不一定等于 MCP Server，也不一定等于 Skill。它们的打包方式、生命周期和权限模型可能完全不同。

## 3. 安装前检查

1. 确认插件来自可信来源。
2. 阅读 README、许可证和依赖说明。
3. 检查插件是否与当前 DSH 版本兼容。
4. 查看插件是否需要访问网络、文件、账号或消息平台。
5. 检查安装脚本和依赖，不要盲目运行未知来源的命令。
6. 准备可恢复的测试环境。

## 4. 安装与配置流程

> 以下为通用流程，具体命令必须从两个插件各自的当前文档中核实后填写。

1. 获取插件源码或发行包。
2. 按插件说明安装依赖。
3. 将插件放入宿主要求的插件目录，或使用宿主支持的安装入口。
4. 根据示例配置填写必要参数。
5. 重启或重新加载宿主（如果该插件机制要求）。
6. 查看加载日志，确认插件成功注册。
7. 使用最小化测试验证插件功能。

## 5. 插件测试记录

每个插件至少记录：

- 安装前置条件。
- 安装过程和版本。
- 配置项含义。
- 成功加载的证据。
- 一次正常调用的输入与输出。
- 一次错误场景及排错方式。
- 插件可能访问的数据和权限。

## 6. 常见问题

- 插件没有出现在列表：检查目录、入口文件、宿主版本和加载日志。
- 插件加载失败：检查依赖版本、配置格式和错误堆栈。
- 调用无响应：检查触发方式、参数结构和宿主事件。
- 功能异常：先使用插件提供的最小示例复现，再排查宿主集成。
- 权限不足：确认插件需要的权限是否已明确授权，不要直接关闭全部安全限制。

## 7. 安全提醒

插件代码可能以宿主进程权限运行。安装插件前必须确认来源、代码行为和权限范围。不要把生产环境密钥放入教学示例，也不要在未审查的情况下运行不可信插件。

## 本节小结

Plugin 的价值在于扩展宿主能力；使用插件时，除了关注“能做什么”，还要关注“它以什么权限做、会访问什么数据”。
