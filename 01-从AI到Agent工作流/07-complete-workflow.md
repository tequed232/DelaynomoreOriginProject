# 完整工作流：让 Agent 协助维护 GitHub 项目

> 本节将 DeepSeekHarness、模型 API、Plugins、Skills 和 GitHub MCP 串联起来，演示一个可控的人机协作流程。

- 难度：🟡 进阶
- 建议学习时间：20～30 分钟
- 状态：依赖前置章节的配置完成情况

## 学习目标

- 理解各组件如何协同。
- 能够设计一个有边界的 Agent 任务。
- 能够检查执行过程和最终结果。

## 1. 工作流结构

```text
用户提出任务
    │
    ▼
DeepSeekHarness
    ├── 模型 API：理解任务、生成计划
    ├── Skill：提供项目维护流程
    ├── Plugins：提供宿主扩展能力
    └── GitHub MCP：读取 GitHub 项目资料
             │
             ▼
       Agent 返回计划
             │
             ▼
       用户检查并授权
             │
             ▼
       Agent 执行获准操作
             │
             ▼
       用户检查结果
```

## 2. 演示任务

示例任务：

> 请检查指定 GitHub 仓库中某个目录的 Markdown 教程，找出失效链接和明显的格式问题。先生成检查报告，不要直接修改文件。

这个任务适合从只读权限开始验证。

## 3. 执行步骤

1. 用户明确仓库和检查范围。
2. Agent 通过 GitHub MCP 读取相关文件。
3. Skill 指导 Agent 按统一规范检查。
4. Agent 输出问题清单和证据。
5. 用户确认问题是否成立。
6. 如需修改，再单独授权创建分支或 PR。
7. 用户审查 PR 并决定是否合并。

## 4. 验收标准

- Agent 没有越过指定仓库和目录范围。
- 报告中的问题能够定位到文件和行。
- 不把猜测描述为已确认错误。
- 未获授权时没有进行写入操作。
- 所有修改都能通过 Git 差异审查。
- 用户能够撤销或拒绝建议的变更。

## 本章总结

这一章从 AI 使用者的判断责任出发，逐步搭建模型、Harness、插件、Skills 和 MCP 的协作流程。

真正可靠的 Agent 工作流，不是让 AI 不受限制地操作，而是让每个组件各司其职，让权限、执行和验收都清晰可见。
